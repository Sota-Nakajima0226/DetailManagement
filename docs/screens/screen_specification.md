## 1. 文書方針

- 本書は画面ごとの目的・主要項目・主要操作・バリデーション観点を定義する。
- 詳細UI（余白、配色、文言トーン等）は別途デザイン時に確定する。

## 2. 画面仕様

## SCR-001 ログイン画面

- 目的: 認証済みユーザーのみ利用可能にする。
- 主要項目:
  - メールアドレス
  - パスワード
- 主要操作:
  - ログイン実行
- バリデーション:
  - メール形式チェック
  - 必須入力チェック
- 備考:
  - 未ログイン時は常に本画面へ遷移
  - ログイン成功後は Supabase SDK がセッション（access_token 等）をブラウザの localStorage 等に保持し、再読み込み後も復元する
  - ログアウトはメイン画面 AppBar のメニューから実行する

## SCR-002 明細一覧画面

- 目的: 当月/過去月の明細確認と絞り込み。
- 主要項目:
  - 対象年月セレクター
  - 取込状況バッジ（例: 「今月: 楽天 ✓ / Amex ✗」）。`GET /statements/upload-status` を参照（表示名は `card_issuers.display_name`）
  - フィルター（カテゴリ・名義人・カード発行会社・未分類）
  - 明細テーブル（利用日、店名、金額、名義人、カード発行会社、カテゴリ、分類元、AI信頼度）
  - 画面下部フッター（ナビ）: 「明細」「グラフ」ほか将来拡張用タブ
- 主要操作:
  - 条件変更で再検索
  - 明細行から仕分け画面へ遷移
  - フッターの「グラフ」でグラフ・集計画面へ切り替え
- 備考:
  - 月間合計や件数をヘッダー表示する想定
  - 当該月にいずれのカードも未アップロードの場合は「対象年月の明細はまだアップロードされていません」を表示する
  - 一部カードのみ取込済みで、絞り込みなしの一覧が空でない場合は通常表示しつつ、未取込カードをバッジで示す
  - 絞り込み中で0件の場合は「条件に該当する明細はありません」を表示する
  - `category_id = NULL` の未分類行は確認が必要な明細として専用色で表示する
  - AI分類済みかつ `AI_CONFIDENCE_REVIEW_THRESHOLD` 以下の行は、未分類とは別の専用色で表示し、AI信頼度を併記する

## SCR-003 明細仕分け画面

- 目的: 自動分類結果の修正と、選んだカテゴリを次回の取込から使うルールにすること。
- 主要項目:
  - 対象明細情報（店名、金額、現カテゴリ、カード発行会社）
  - カテゴリ選択
  - 「この店名を分類ルールに追加する」チェック（初期値はオフ）
- 主要操作:
  - チェックがオフの保存は、明細のカテゴリだけを更新して画面を閉じる
  - チェックがオンの保存はダイアログを出す。ダイアログは確認の二度問いにしない
- ダイアログ:
  - 支払い名はテキスト。初期値は編集中の明細の店名
  - 正規表現チェックの初期値はオフ
  - 分類先は、画面で選んでいるカテゴリ名のテキスト。ダイアログでは変更できない
  - 優先度は出さない
  - ヒントは、正規表現オフのとき「この文字を含む店名」、オンのとき「正規表現としてマッチ」
  - ボタンは「追加して保存」と「戻る」
- 「戻る」:
  - 明細もルールも保存しない。API は呼ばない
  - チェック、選択中カテゴリ、編集した支払い名、正規表現フラグは、仕分け画面を閉じるまで残す。次にダイアログを開いたときはその内容を出す
- 保存しない条件:
  - カテゴリ未選択では保存できない。チェックはオフのまま操作できない
  - カテゴリが今と同じでも、チェックはオンにできる（AI の結果をルールに固定する）
  - 支払い名は、前後の空白を除いたあとに文字が残らなければ保存しない。ダイアログに留まり、API は呼ばない
  - 正規表現オンで、パターンが Python の `re.compile` できないときは、明細もルールも保存しない。ダイアログに留まる。判定は `POST /rules/validate` の 400 に合わせ、Dart の正規表現では判定しない
- 保存の順序（検証が通ったあと）:
  - 先にこの明細だけを PATCH する。`classified_by = manual` のまま。同じ月の他の行は変えない
  - 続けてルールを保存する。同じルールとは、前後の空白を除いたパターン文字列が一致し、かつ `is_regex` が一致する行。大文字小文字は区別する。意味が同じ正規表現かどうかは見ない。1件以上あれば行を増やさず、そのすべてを選択中カテゴリと新しい優先度で更新する。無ければ 1 件作る
  - 優先度は、保存時点の全ルールの最大値 + 10。ルールが無ければ 10。ダイアログには出さない。SCR-007 で後から変更できる
  - PATCH のあとルール保存だけ失敗したときは「明細は保存しました。ルールの追加に失敗しました」と出し、仕分け画面は閉じない
  - 明細とルールの両方が成功したら画面を閉じる
  - 追加・更新したルールが効くのは次回の取込から

## SCR-004 グラフ・集計画面

- 目的: 家計状況をカテゴリ別に可視化する。
- 主要項目:
  - 表示切替タブ（年月セレクター下部）
    - 「カテゴリ別」: 当月合計＋円グラフ＋カテゴリ別バー＋名義人別合計
    - 「月次推移」: 当月合計＋月次推移グラフ＋名義人別合計
  - 取込状況バッジ（SCR-002 と同様、未取込カードを可視化）
  - カード発行会社フィルタ（任意。未指定は全発行会社の明細に、手動支払いと対象月に有効な固定費を合算する。指定時はそのカードの明細だけ）
  - 当月合計表示カード（タブの直下。対象年月の合計金額をハイライト表示。表示条件は備考）
  - 円グラフ（ドーナツ型、カテゴリ毎の構成比をスライス表示。色は `categories.color` を使用、5%以上のスライスには内部に `%` を表示）
    - スライスをタップすると該当カテゴリがハイライトされ、グラフ下部にカテゴリ名・金額・割合を表示。再タップ／別スライスタップで切替・解除。
  - カテゴリ別バー（カテゴリ毎に `categories.color` で着色した横棒）
  - 棒グラフ（月次推移）: 選択月を含む過去6ヶ月のカテゴリ別積み上げ棒グラフ。色は `categories.color` を使用し、未分類は灰色。下部にカテゴリ凡例を表示。
  - 名義人別合計（金額と全体に占める割合 % を併記）
  - ヘッダー: アップロード遷移ボタン、設定系メニュー（カテゴリ管理／分類ルール管理／固定費管理／手動支払い登録／取込プロファイル管理※低優先）
  - 画面下部フッター（ナビ）: 「明細」「グラフ」ほか将来拡張用タブ
- 主要操作:
  - 対象月切り替え（年・月プルダウンと前後の月送りボタン）
  - 表示切替タブで「カテゴリ別」「月次推移」を切り替え
  - フッターの「明細」で明細一覧画面へ切り替え
  - ヘッダーから明細アップロード／設定系画面への遷移
  - 前月比較表示（将来）
- 備考:
  - 検索条件（絞り込み）ボタンは明細一覧画面のみ表示（本画面では表示しない）。カード発行会社フィルタは集計用の簡易切替として本画面に置いてよい
  - 取込の有無にかかわらず、カテゴリ別・名義人別・月次推移の3本を取得する。未指定は合算、指定時は3本すべてに同じ `card_issuers.code` を渡す
  - 表示中の絞り込みで当月のカテゴリ合計が1件以上あれば、集計カードとタブを出す。明細が無い月でも、固定費か手動があればグラフが出る
  - 当月のカテゴリ合計が空、かつ `upload-status` の `uploaded` が空のときだけ「対象年月の明細はまだアップロードされていません」を出し、集計カードとタブは出さない
  - アップロードが1件以上あるのに絞り込み結果が空のときは、集計カードとタブを出す
  - 未取込バッジは、グラフを出す場合も出さない場合も残す

## SCR-005 アップロード画面

- 目的: 夫が月次明細を登録する（複数カードの作業をできるだけ簡略化する）。
- 入口: アプリ内の遷移に加え、パス `/upload` から直接開く。`year` と `month` が両方そろって月が 1〜12 のとき、その値を対象年月の初期値にする。クエリが無い、または不正なら今日の年月。未ログイン時はログイン後にこの画面へ戻る。LINE の取込依頼はこの URL を案内する（`docs/notifications/line_notification.md`）。
- 主要項目:
  - 対象年月指定
  - 取込状況表示（未取込の issuer を強調）
  - ファイル選択（CSV。**複数選択可**）
  - ファイルごとの issuer 自動判定結果（`POST /statements/detect-issuer`）。表示名で見せ、誤判定時は有効 issuer 一覧から手動修正
  - 取込結果（issuer ごと: 件数・未分類件数・エラー件数）
- 主要操作:
  - 複数 CSV を選択 → 自動判定結果を**確認・修正** → アップロード実行
  - 同一年月・同一 issuer の既存データがある場合は置換確認ダイアログを表示
- バリデーション:
  - 拡張子・CSV形式チェック
  - issuer 未確定のファイルはアップロード不可（手動選択するまで）
  - 同一リクエスト内で同じ issuer が重複した場合はエラー
- 備考:
  - 変換は DB の取込プロファイル＋汎用エンジン。会社専用パーサ画面は持たない
  - PDF は本画面の対象外（将来）。UI に PDF を出さない
  - 完了時に LINE グループへアップロード完了を通知する（`docs/notifications/line_notification.md`）
  - 再アップロードは issuer 単位で置換。手動仕分け保持は将来課題

## SCR-006 カテゴリ管理画面

- 目的: 分類カテゴリを管理する。
- 主要項目:
  - カテゴリ一覧（名称、色、表示順）
  - 新規作成/編集フォーム
- 主要操作:
  - 追加・更新・削除
- バリデーション:
  - 名称必須
  - 表示順は数値

## SCR-007 分類ルール管理画面

- 目的: 店名パターン分類ルールのメンテナンス。
- 主要項目:
  - ルール一覧（パターン、正規表現フラグ、カテゴリ、優先度）
  - ルール編集フォーム
- 主要操作:
  - 追加・更新・削除
- バリデーション:
  - パターン必須
  - 優先度は `0` 以上の整数

## SCR-008 固定費管理画面

- 目的: 固定費マスターの登録と履歴管理。
- 主要項目:
  - 固定費一覧（名称、金額、カテゴリ、適用期間）
  - 作成/編集フォーム
- 主要操作:
  - 追加・更新・無効化
- バリデーション:
  - 金額は0より大きい整数
  - `valid_from <= valid_until`（終了日入力時）

## SCR-009 手動支払い登録画面

- 目的: カード明細外の支払いを補完する。
- 主要項目:
  - 利用日
  - 店名
  - 金額
  - カテゴリ
  - 名義人
  - メモ（任意）
- 主要操作:
  - 新規登録・編集・削除
- バリデーション:
  - 利用日、店名、金額、カテゴリは必須

## SCR-010 取込プロファイル管理画面

- 目的: カード発行会社マスタと CSV 取込プロファイルを管理し、カード追加時にソース修正なしで対応する。
- 優先度: **低**（当面は API / SQL でメンテ。画面は後回しでよい）
- 主要項目:
  - issuer 一覧（code、表示名、リマインド対象、有効／無効）
  - 取込プロファイル編集（encoding、header_signature、column_mapping、transforms、skip_rules）
  - `custom_hook` は高度設定として任意表示（通常は空）
- 主要操作:
  - issuer / プロファイルの追加・更新・無効化
- バリデーション:
  - `code` 必須・ユニーク
  - `column_mapping` に利用日・店名・金額の対応が必要（名義人は任意＋デフォルト値可）

## 3. 共通仕様

- 認証必須画面:
  - SCR-002 以降はログイン済みユーザーのみ表示。
- API 呼び出し:
  - ログイン済みセッションの access_token を `Authorization: Bearer` で FastAPI に付与する。
  - API が 401 を返した場合は自動ログアウトし、SCR-001 へ戻る。
- エラー表示:
  - APIエラー時はトーストまたはダイアログでユーザーに通知。
- レスポンシブ:
  - スマホ優先で設計し、PC表示は横幅を活かして情報量を増やす。
- カード発行会社の表示名:
  - `card_issuers.display_name` を用いる（ハードコードしない）
