## 1. 文書方針

- 本書は画面ごとの目的・主要項目・主要操作・バリデーション観点を定義する。
- 詳細UI（余白、配色、文言トーン等）は別途デザイン時に確定する。

## 2. 画面仕様

## SCR-001 ログイン画面

- 目的: 認証済みユーザーのみ利用可能にする。
- 主要項目:
  - メールアドレス
  - パスワード
- 主要操作:
  - ログイン実行
- バリデーション:
  - メール形式チェック
  - 必須入力チェック
- 備考:
  - 未ログイン時は常に本画面へ遷移
  - ログイン成功後は Supabase SDK がセッション（access_token 等）をブラウザの localStorage 等に保持し、再読み込み後も復元する
  - ログアウトはメイン画面 AppBar のメニューから実行する

## SCR-002 明細一覧画面

- 目的: 当月/過去月の明細確認と絞り込み。
- 主要項目:
  - 対象年月セレクター
  - 取込状況バッジ（例: 「今月: 楽天 ✓ / Amex ✗」）。`GET /statements/upload-status` を参照（表示名は `card_issuers.display_name`）
  - フィルター（カテゴリ・名義人・カード発行会社・未分類）
  - 明細テーブル（利用日、店名、金額、名義人、カード発行会社、カテゴリ、分類元、AI信頼度）
  - 画面下部フッター（ナビ）: 「明細」「グラフ」ほか将来拡張用タブ
- 主要操作:
  - 条件変更で再検索
  - 明細行から仕分け画面へ遷移
  - フッターの「グラフ」でグラフ・集計画面へ切り替え
- 備考:
  - 月間合計や件数をヘッダー表示する想定
  - 当該月にいずれのカードも未アップロードの場合は「対象年月の明細はまだアップロードされていません」を表示する
  - 一部カードのみ取込済みで、絞り込みなしの一覧が空でない場合は通常表示しつつ、未取込カードをバッジで示す
  - 絞り込み中で0件の場合は「条件に該当する明細はありません」を表示する
  - `category_id = NULL` の未分類行は確認が必要な明細として専用色で表示する
  - AI分類済みかつ `AI_CONFIDENCE_REVIEW_THRESHOLD` 以下の行は、未分類とは別の専用色で表示し、AI信頼度を併記する

## SCR-003 明細仕分け画面

- 目的: 自動分類結果の修正と分類精度向上。
- 主要項目:
  - 対象明細情報（店名、金額、現カテゴリ、カード発行会社）
  - カテゴリ選択
  - 「ルール追加提案」チェックまたは確認ダイアログ
- 主要操作:
  - カテゴリ更新（PATCH）
  - ルール追加（任意）
- バリデーション:
  - カテゴリ未選択で保存不可

## SCR-004 グラフ・集計画面

- 目的: 家計状況をカテゴリ別に可視化する。
- 主要項目:
  - 表示切替タブ（年月セレクター下部）
    - 「カテゴリ別」: 当月合計＋円グラフ＋カテゴリ別バー＋名義人別合計
    - 「月次推移」: 当月合計＋月次推移グラフ＋名義人別合計
  - 取込状況バッジ（SCR-002 と同様、未取込カードを可視化）
  - カード発行会社フィルタ（任意。未指定時は両社合算）
  - 当月合計表示カード（タブ切替直下に常時表示、対象年月の合計金額をハイライト表示）
  - 円グラフ（ドーナツ型、カテゴリ毎の構成比をスライス表示。色は `categories.color` を使用、5%以上のスライスには内部に `%` を表示）
    - スライスをタップすると該当カテゴリがハイライトされ、グラフ下部にカテゴリ名・金額・割合を表示。再タップ／別スライスタップで切替・解除。
  - カテゴリ別バー（カテゴリ毎に `categories.color` で着色した横棒）
  - 棒グラフ（月次推移）: 選択月を含む過去6ヶ月のカテゴリ別積み上げ棒グラフ。色は `categories.color` を使用し、未分類は灰色。下部にカテゴリ凡例を表示。
  - 名義人別合計（金額と全体に占める割合 % を併記）
  - ヘッダー: アップロード遷移ボタン、設定系メニュー（カテゴリ管理／分類ルール管理／固定費管理／手動支払い登録／取込プロファイル管理※低優先）
  - 画面下部フッター（ナビ）: 「明細」「グラフ」ほか将来拡張用タブ
- 主要操作:
  - 対象月切り替え（年・月プルダウンと前後の月送りボタン）
  - 表示切替タブで「カテゴリ別」「月次推移」を切り替え
  - フッターの「明細」で明細一覧画面へ切り替え
  - ヘッダーから明細アップロード／設定系画面への遷移
  - 前月比較表示（将来）
- 備考:
  - 検索条件（絞り込み）ボタンは明細一覧画面のみ表示（本画面では表示しない）。カード発行会社フィルタは集計用の簡易切替として本画面に置いてよい
  - 当該月にいずれのカードも未アップロードの場合は集計カードとタブを表示せず「対象年月の明細はまだアップロードされていません」を表示する

## SCR-005 アップロード画面

- 目的: 夫が月次明細を登録する（複数カードの作業をできるだけ簡略化する）。
- 主要項目:
  - 対象年月指定
  - 取込状況表示（未取込の issuer を強調）
  - ファイル選択（CSV。**複数選択可**）
  - ファイルごとの issuer 自動判定結果（`POST /statements/detect-issuer`）。表示名で見せ、誤判定時は有効 issuer 一覧から手動修正
  - 取込結果（issuer ごと: 件数・未分類件数・エラー件数）
  - （任意）リマインド用 `.ics` ダウンロードリンク
- 主要操作:
  - 複数 CSV を選択 → 自動判定結果を**確認・修正** → アップロード実行
  - 同一年月・同一 issuer の既存データがある場合は置換確認ダイアログを表示
- バリデーション:
  - 拡張子・CSV形式チェック
  - issuer 未確定のファイルはアップロード不可（手動選択するまで）
  - 同一リクエスト内で同じ issuer が重複した場合はエラー
- 備考:
  - 変換は DB の取込プロファイル＋汎用エンジン。会社専用パーサ画面は持たない
  - PDF は本画面の対象外（将来）。UI に PDF を出さない
  - 完了時に妻へ通知送信
  - 再アップロードは issuer 単位で置換。手動仕分け保持は将来課題

## SCR-006 カテゴリ管理画面

- 目的: 分類カテゴリを管理する。
- 主要項目:
  - カテゴリ一覧（名称、色、表示順）
  - 新規作成/編集フォーム
- 主要操作:
  - 追加・更新・削除
- バリデーション:
  - 名称必須
  - 表示順は数値

## SCR-007 分類ルール管理画面

- 目的: 店名パターン分類ルールのメンテナンス。
- 主要項目:
  - ルール一覧（パターン、正規表現フラグ、カテゴリ、優先度）
  - ルール編集フォーム
- 主要操作:
  - 追加・更新・削除
- バリデーション:
  - パターン必須
  - 優先度は `0` 以上の整数

## SCR-008 固定費管理画面

- 目的: 固定費マスターの登録と履歴管理。
- 主要項目:
  - 固定費一覧（名称、金額、カテゴリ、適用期間）
  - 作成/編集フォーム
- 主要操作:
  - 追加・更新・無効化
- バリデーション:
  - 金額は0より大きい整数
  - `valid_from <= valid_until`（終了日入力時）

## SCR-009 手動支払い登録画面

- 目的: カード明細外の支払いを補完する。
- 主要項目:
  - 利用日
  - 店名
  - 金額
  - カテゴリ
  - 名義人
  - メモ（任意）
- 主要操作:
  - 新規登録・編集・削除
- バリデーション:
  - 利用日、店名、金額、カテゴリは必須

## SCR-010 取込プロファイル管理画面

- 目的: カード発行会社マスタと CSV 取込プロファイルを管理し、カード追加時にソース修正なしで対応する。
- 優先度: **低**（当面は API / SQL でメンテ。画面は後回しでよい）
- 主要項目:
  - issuer 一覧（code、表示名、リマインド対象、有効／無効）
  - 取込プロファイル編集（encoding、header_signature、column_mapping、transforms、skip_rules）
  - `custom_hook` は高度設定として任意表示（通常は空）
- 主要操作:
  - issuer / プロファイルの追加・更新・無効化
- バリデーション:
  - `code` 必須・ユニーク
  - `column_mapping` に利用日・店名・金額の対応が必要（名義人は任意＋デフォルト値可）

## 3. 共通仕様

- 認証必須画面:
  - SCR-002 以降はログイン済みユーザーのみ表示。
- API 呼び出し:
  - ログイン済みセッションの access_token を `Authorization: Bearer` で FastAPI に付与する。
  - API が 401 を返した場合は自動ログアウトし、SCR-001 へ戻る。
- エラー表示:
  - APIエラー時はトーストまたはダイアログでユーザーに通知。
- レスポンシブ:
  - スマホ優先で設計し、PC表示は横幅を活かして情報量を増やす。
- カード発行会社の表示名:
  - `card_issuers.display_name` を用いる（ハードコードしない）
