## 背景・ゴール

仕分け画面で、選んだカテゴリを次回の取込からも使うルールにできるようにする。チェックがオフなら今までどおり明細だけを保存する。チェックがオンのときは、支払い名を直してからルールを保存する。完了時点で、短い店名の一部は正規表現なしで登録でき、そのルールは既存ルールより先に評価される。

## 現状ギャップ

- SCR-003 はカテゴリの PATCH だけで、ルール追加のチェックもダイアログも無い
- 画面仕様は「チェックまたは確認ダイアログ」とだけ書いてあり、パターン編集、正規表現、優先度、既存ルールの更新が決まっていない
- 設計メモの流れは、店名そのものを YES/NO で足すだけになっている
- `POST /rules` と `PUT /rules/{id}` は、コンパイルできない正規表現も保存する。取込時の `re.search` は不正なパターンで例外になる
- 既存ルールの優先度は 160〜220。追加時の既定 0 のままだと、より高い既存ルールに含まれる店名では新しいルールが使われない

## 決定済み方針（本計画内）

- 仕分け画面に「この店名を分類ルールに追加する」チェックを置く。初期値はオフ。カテゴリ未選択のときはオフのまま操作できない。カテゴリが今と同じでもオンにできる（AI の結果をルールに固定する）
- チェックがオフの保存は、今どおり明細のカテゴリだけを更新して画面を閉じる
- チェックがオンの保存ではダイアログを出す。ダイアログは確認の二度問いにしない
- ダイアログの支払い名はテキストで、初期値は編集中の明細の店名。正規表現チェックの初期値はオフ。分類先は画面で選んでいるカテゴリ名のテキストで、ダイアログでは変更できない。優先度は出さない
- ヒントは、正規表現オフのとき「この文字を含む店名」、オンのとき「正規表現としてマッチ」
- ボタンは「追加して保存」と「戻る」。戻るでは明細もルールも保存しない。チェック、選択中カテゴリ、編集した支払い名、正規表現フラグは、仕分け画面を閉じるまで残す。次にダイアログを開いたときはその内容を出す
- 支払い名は trim 後が空なら保存しない。ダイアログに留まり、API は呼ばない
- 正規表現オンでパターンが Python `re.compile` できないときは、明細もルールも保存しない。ダイアログに留まる。判定は Dart の正規表現ではなく API に合わせる
- 保存順は、検証が通ったあと明細の PATCH、そのあとルール。PATCH のあとルール保存だけ失敗したら「明細は保存しました。ルールの追加に失敗しました」と出し、仕分け画面は閉じない
- 同じルールとは、trim 後のパターン文字列が一致し、かつ `is_regex` が一致する行。大文字小文字は区別する。意味が同じ正規表現かどうかは見ない。1件以上あれば行を増やさず、そのすべてを選択中カテゴリと新しい優先度で更新する。無ければ1件作る
- 優先度は保存時点の全ルールの最大値 + 10。ルールが無ければ 10。ダイアログには出さない。SCR-007 で後から変更できる
- この明細は `classified_by = manual` のまま。同じ月の他の行は変えない。ルールが効くのは次回の取込から
- マッチの意味は変えない。オフは部分一致、オンは `re.search`。同点の優先度は id が小さい方を先に評価する
